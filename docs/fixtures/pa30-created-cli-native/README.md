# Rust-created managed PE PA30 native validation

All 36 final Rust-created patches passed native Apply exactly, with source SHA-256 values unchanged. Native headers confirm modern managed graph 16 or 32, file-type set 245, SHA-1 and zero FILETIME. The current manifest and native execution records describe this successful gate.

This fixture tree copies five families of original C# inputs across AnyCPU, x86 and x64 platforms from `pa30-pe32-native`. Six additional header-only directions modify the original basic assemblies' COFF timestamp and checksum. Input DLL bytes are never executed. `prepare_inputs.py` and `inputs.json` preserve deterministic input derivation, SHA-256 values and sizes; original C# source and compiler provenance remain in the earlier fixture trees.

`generate.py` creates both modern managed `create --format pa30 --pe` and RAW controls. Native `ApplyDeltaB` checks target bytes, source hashes and `GetDeltaInfoB` header fields through `apply.ps1`. The public oracle is Windows 10 build 19045.5073, `msdelta.dll` SHA-256 `098a2a12856c374b418013a1806a9f9f14517c733aed83886ec657c21b57d755`, file version `5.00 (WinBuild.160101.0800)`, running in the disposable `cbs-psfx-pre-esu-1004` VM with `VM_NET=none`. The wrapper compiler version is 4.8.4084.0. Microsoft binaries remain outside the repository.

The first independent gate accepted 24 of 36 Rust-created patches. It rejected the signatures and attributes families' metadata-normalized patches with native error 13. `rejected-first-gate` retains those 12 patches and the complete initial execution evidence. `diagnostic-rust` isolates flags: zero and IL-only passed, while metadata-only and combined failed, while corrected AMD64 map probes isolate the TypeDef table2 mapping. The first isolated-map harness paired the wrong architecture inputs; that rejected run is explicitly labeled `mismatched-source` and excluded from codec conclusions. `diagnostic-native` retains eight independently native-created flag-isolated controls, all accepted on the same inputs. `diagnostic-editable` captures native source normalization by pinning a disposable source copy with `Editable=TRUE`; native Apply leaves that copy entirely zeroed after rejection, so this probe does not reveal normalized source bytes. The original disk inputs remain unchanged. `diagnostic-nohash` instead uses research patches with algorithm 0 and no target hash to copy the complete native normalized dictionary to output; all six probes succeeded and enabled byte-level comparison. These hashless diagnostics are separate from production SHA-1 creation. The failure was the native StandAloneSig local-signature quirk: only the first local is normalized even when the encoded count is larger. After matching that behavior, the complete 36-case gate passed. Historical diagnostics remain separate from final production SHA-1 evidence.

All final managed controls remain 208–1,638 bytes larger than their RAW creation controls because metadata preprocessing overhead dominates these inputs; no compression improvement is claimed for this matrix.

For reproduction, build the standalone CLI with `cargo build --locked -p windows-delta --features cli`. Use a disposable copy of this tree without generated outputs, then `WINDOWS_DELTA_CLI=/absolute/path/to/windows-delta python3 generate.py`; the CLI refuses existing outputs. Transfer each manifest row's source, target and delta as `<name>.source`, `<name>.target`, `<name>.delta` into `C:\pa30-created-cli-oracle`, together with `manifest.json` and `apply.ps1`, then run PowerShell with `-NoProfile -ExecutionPolicy Bypass -File C:\pa30-created-cli-oracle\apply.ps1`. Regeneration replaces manifests with fresh encoder evidence; retain historical rejection records separately.
