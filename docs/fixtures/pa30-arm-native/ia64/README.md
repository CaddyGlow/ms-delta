# Original IA64 parser and transform controls

These original PE64 images use machine 0x200, three authored 16-byte IA64 instruction bundles (GP-relative addl, short branch and long branch), two 12-byte pdata records, global-pointer directory values and data/pdata/relocation RVA geometry shifted by 0x1000. The image base also changes. The pointer relocation is initially DIR64. Inputs are never executed; generate_inputs.py deterministically regenerates them and records hashes.

The latest pinned UpdateCompression.dll accepted 12 PA30 and 12 PA31 isolated forward/reverse cases, actual graph 4/set15. The older pinned Windows 19041 msdelta.dll accepted another 12 PA30 cases in legacy-msdelta with MD5 target hashes. These native implementations differ: the latest DLL does not perform the IA64 instruction/pdata passes, while the older DLL does. The separate native dictionary probes establish the source-normalization difference. Tests and documentation must retain that distinction rather than infer flag semantics solely from a header. Unsupported file-type set7 requests returned native error269569; labeled negative proof is retained.

The sibling ia64-imm64 tree clones the original images and changes only relocation kind10 to kind9 at the pinned entry, retaining unchanged operand bytes; all four latest and four older native flag32/full cases passed. This is an operand-type dispatch control, not a claim that the original DIR64 pointer bytes encode an executable movl instruction. Both DLL hashes and public API provenance are documented in the PA30/PA31 native fixture trees; Microsoft binaries remain cache-only.
