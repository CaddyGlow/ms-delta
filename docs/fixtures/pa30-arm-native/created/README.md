# Rust-created ARM, ARM64 and IA64 PA30/PA31 native validation

All 12 final Rust-created patches reproduced their exact targets under the pinned native UpdateCompression.dll: ARM, ARM64 and IA64, forward/reverse, PA30/PA31. Inline native proof includes actual graph, flags, target hashes and unchanged source SHA-256 values. PA30 uses SHA-1 and PA31 uses SHA-256; target FILETIME is zero. Original inputs, build/generation provenance and native decoding matrices are retained in the sibling architecture directories. Inputs are never executed.

The initial gate rejected eight ARM/IA64 patches. `rejected-first-gate` preserves those patches and execution proof. ARM creation was corrected to match the native treatment of MOV32T relocation kind7 and original source ImageBase. IA64 creation restricts its normalization candidates to the common zero/relocation modes because the old MSDelta and current UpdateCompression implementations differ in instruction/pdata transforms. The final gate passes all 12 cases; failed historical diagnostics are excluded from that claim.

`generate.py` invokes `create --format pa30|pa31 --pe`; reproduce in a copy without outputs, using `WINDOWS_DELTA_CLI=/absolute/path/to/windows-delta python3 generate.py`. Native `apply.ps1` uses the pinned DLL SHA-256 `2a12118232d0faab12bc8c768391ebd75c9160674a68c7cf8ac4bb24bdd2eefa` at `C:\pa31-oracle\UpdateCompression.dll` and named inputs/deltas under `C:\pa30-created-cli-oracle`. Native platform and compiler provenance match `pa31-native`. This gate proves patch compatibility for these original images, not universal architecture transform coverage or executable IA64/ARM programs.
